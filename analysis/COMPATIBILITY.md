# Совместимость 0.3.0

Хеш `Assembly-CSharp.dll` отмечает известную сборку в диагностике. Отличающийся хеш сам по себе не запрещает установку, патчи или работу функций. Проверенная среда: Windows x64, Unity Mono 6000.2.8f1, Steam build 25936063, BepInEx 5.4.23.5.

## Проверки функций

`GameApiContracts` проверяет используемые поля, методы, свойства и индексаторы: имена, типы, сигнатуры, возвращаемые значения и необходимые аксессоры. Для полей и методов также проверяется принадлежность экземпляру или классу. Каждая проверка выполняется отдельно.

| Функция | Основные контракты | Зависимости |
| --- | --- | --- |
| Catalog | CatInventory, SteamItemRuntime, SteamItemIdReference | — |
| Appearance | Cat, CatCosmetics, MemoryImageCache | Catalog |
| Sharing | LobbyData, LobbyMemberData и индексатор метаданных | Appearance |
| Emotes | EmoteSpawner, SteamMultiplayer.SendEmote | Catalog |
| Wheel | EmoteDonut: коллекция, состояние, геометрия и методы | Catalog |
| Balance | Pets: счётчики, инициализация, UpdateStats | — |
| Automation | Shop, ShopItem: доступность, цена, callback | Balance |
| Gifts | OpenChestForMember и контракты лобби | Automation |
| Previews | изображения Cat и SteamItemRuntime | Catalog |
| Input | InputFieldCache.FocusingInputField | — |

Подарки проверяют контракты лобби самостоятельно: ошибка публикации внешности не должна блокировать покупку собственного сундука. Ошибка счётчиков отключает оба пути расходования очков. Команды изменения баланса проверяют доступность до обращения к Steam.

Группы Harmony принадлежат отдельным функциям. При ошибке выполнения отключается функция, снимаются её патчи и патчи зависимых функций. Для колеса выполняется попытка восстановления штатных родителей элементов и ёмкости. Остальные сервисы продолжают свои обновления. Отражённые поля разрешаются по требованию, чтобы отсутствие одного поля не ломало общий статический инициализатор.

Отключение действует до перезапуска. Оно не записывает выключенные режимы в конфиг. После обновления исправленного мода или игры проверки выполняются заново. Подробности доступны в General и `BepInEx/LogOutput.log`.

## Каталог и границы поддержки

Каталог читается из загруженных игровых данных. Новые ID не требуют правки списка в моде, если игра сохраняет используемый формат предметов и слотов. Сохранённые неизвестные ID пропускаются при восстановлении внешности. Предмет должен присутствовать в ресурсах установленной игры.

Проверка сигнатур не проверяет смысл реализации: метод с прежней сигнатурой может начать вести себя иначе. Значительные изменения типов, Unity, Mono, переход на IL2CPP или несовместимость загрузчика могут помешать загрузить сам плагин. Для таких обновлений потребуется новый релиз. Автоматического скачивания обновлений и обещания совместимости со всеми будущими версиями нет.

## Проверка релиза

```powershell
./scripts/Build.ps1
dotnet build tests/BongoCat.Mod.RuntimeTests/BongoCat.Mod.RuntimeTests.csproj -c Release -p:UseSharedCompilation=false -p:BuildProjectReferences=false
```

Build запускает 68 локальных проверок, включая проверку контрактов на установленных игровых сборках, отклонение изменённых сигнатур и независимость отказов.

Для проверки под Mono при закрытой игре установите основной релиз и временно скопируйте `BongoCat.Mod.RuntimeTests.dll` из `tests/BongoCat.Mod.RuntimeTests/bin/Release/net472/` в папку основного плагина. Запустите игру через Steam с аргументами:

```text
--bongocat-compatibility-check --compat-report=C:\absolute\path\runtime-compatibility.txt
```

Используйте абсолютный путь без пробелов либо передайте весь аргумент отчёта в кавычках. Тест отключает автоматические покупки и подарки в памяти, имитирует отказы отдельных функций, записывает отчёт и закрывает игру. Он не меняет баланс; обычное восстановление сохранённой внешности и её публикация в лобби остаются частью запуска. После проверки удалите тестовую DLL перед обычной игрой. Она не входит в релизный архив.

На проверенной сборке пройдены все 11 проверок в игре. Подтверждены запуск контрактов под Mono, независимые владельцы патчей, инициализация колеса, снятие патчей при отказах, сохранение локальной внешности при отказе публикации, блокировка расходования при отказе счётчиков и доступность окна Mods. Это проверка обработки отказов на текущем клиенте, а не испытание ещё не выпущенной версии игры.
