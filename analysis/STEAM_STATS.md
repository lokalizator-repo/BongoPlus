# Ограничения Steam-статистики

Проверено 2026-10-19 в локальном `Steam/appcache/stats/UserGameStatsSchema_3419430.bin`.
SHA-256: `99c1e09d578becc397b827660ff1d42ae6266f2024c52798e95c476583022880`.

В бинарной KeyValues-схеме у определений BongoTap (ID 4), BongoMinus (ID 10) и BongoBeat (ID 3) записаны `type = INT` и `incrementonly = 1`.

Версия 0.1.1 пыталась вычислить BongoTap как BongoMinus + target, что для меньшего target уменьшало BongoTap. Такое уменьшение противоречит схеме. Ошибка `Steam refused the balance change` не различала два вызова SetStat.

Версия 0.1.2 строит пару:

```
nextGained = max(currentGained, currentSpent + target)
nextSpent = nextGained - target
```

При корректных исходных значениях это сохраняет монотонность обоих счётчиков и меняет максимум один из них. Если nextGained превышает игровой предел 2147483646, запрос отклоняется до вызова Steam. Restore восстанавливает доступный остаток через тот же расчёт, а не уменьшает исторические счётчики. Локальный откат принятого SetStat уменьшением значения не используется.

SetStat меняет локальный кэш Steam; сохранение отдельно подтверждается UserStatsStored. Это различие описано в [документации ISteamUserStats](https://partner.steamgames.com/doc/api/isteamuserstats). При отказе записи лог теперь указывает имя счётчика и точные значения.

Вывод о причине основан на схеме и несовместимом расчёте, а не на переборе серверных ограничений. Исправление проверено тестами; повторный реальный SetStat должен выполнить пользователь с выбранным им балансом.
